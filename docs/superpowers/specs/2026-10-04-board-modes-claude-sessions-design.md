# Board modes, Claude sessions, voice commands and remote use: design

Date: 2026-10-04. Status: approved in conversation (all sections); the user asked to build every phase to completion.
Builds on: `2026-10-04-claude-companion-design.md` (Allow/Deny over BLE, already shipped on branch `claude-companion`).

## Goal

The board stays a translator first. Claude is a secondary, battery-frugal mode that works like a mini
Remote Control: pick a Claude Code session, get progress notifications, choose Claude's proposed options
on the touch screen, and give commands by voice. It works near the Mac (BLE) and away from it (through the iPhone).

Agreed constraints:
- Claude Code sessions run on the user's Mac (the user drives them from the phone with Remote Control).
- Voice commands go into an already-open session; this requires the session to run inside tmux (a `cb` launcher is provided).
- Battery is 550 mAh: Claude features must cost nothing while unused.
- Nothing is ever auto-approved; every answer comes from an explicit tap; voice text is always confirmed before sending.
- No unofficial Anthropic APIs, no reading other apps' data on the iPhone, no use of the user's claude.ai credentials.

## Phase 1: board shell (buttons, lock screen, modes)

Modes: **Translator** (default), **Claude**, **Session picker**, **Locked**.

| Input | Unlocked | Locked |
|---|---|---|
| PWR ×1 | Lock | Unlock (to the mode in use before locking) |
| PWR ×2 | Claude mode | Unlock → Claude mode |
| PWR ×3 | Session picker | Unlock → Session picker |
| PWR hold 3 s | Power off (battery) / screen off (USB) — unchanged | same |
| BOOT ×1 | Translator mode | Unlock → Translator mode |
| Tap ×1 on screen | normal UI | Show the lock face for 5 s: animated pixel cat, clock, battery % |
| Tap ×2 on screen | (Translator: toggles screen off as today) | Unlock |

- Locked = panel off and touch inert except the two lock gestures; BLE links, translation and Claude notifications keep running.
  An important Claude event (permission request, question, focused-session "needs you") wakes the panel and shows it;
  the user still answers with taps (the arming delay applies).
- Battery % moves from PWR ×1 to the lock face.
- Clock: the iPhone (translator link) and the Mac (Claude link) send the current time (UTC + offset) on connect;
  the board keeps time with its RTC timer. If no time is known yet, the face shows "--:--".
- Pixel cat: original pixel-art frames generated by a script in the repo (no third-party art), stored as an LVGL
  animation (image list), animated only while the lock face is visible.
- Deep sleep rules unchanged (battery only, no link for 3 min).

## Phase 2: Claude sessions near the Mac (BLE)

### Session tracking (Mac daemon)
- Additional hooks, all `async: true` except the existing PermissionRequest: `SessionStart`, `SessionEnd`,
  `UserPromptSubmit`, `Stop`, `Notification` (all types). The hook CLI also forwards `$TMUX_PANE` (and tmux socket)
  from its environment when present.
- Per session: `session_id`, project (basename of cwd), state, started/updated time, last assistant line
  (from the transcript on Stop), `tmux_pane` (optional).
- States: **working** (after UserPromptSubmit), **needs you** (pending PermissionRequest or AskUserQuestion),
  **idle** (after Stop / idle_prompt), **ended** (SessionEnd; dropped after 10 min).
  If SessionStart/SessionEnd hooks are not available in settings hooks, sessions are created on first event and
  ended after 2 h without events.

### Board UI
- **Session picker** (PWR ×3): up to 6 rows, "needs you" first, then most recent. Row = coloured dot
  (red needs you, yellow working, green idle, grey ended) + project + short state. Tap a row → focus it → Claude screen.
  A badge counts unseen "done" events of non-focused sessions.
- **Claude screen** (PWR ×2): focused session's project, state, elapsed time, last assistant line; 🎤 button (Phase 3).
- Notifications:
  - Focused session done → chime + last line.
  - Focused session needs you → wake + show the request.
  - Non-focused session done → silent, badge only.
  - Any session's permission request or question → shown (project tagged); it must not stall Claude.
- Data to the board only while in Claude/picker mode, plus important events in any mode; state changes are sent as
  small deltas.

### Answering
- **Permission request**: Allow / Deny / **Always allow** (only if the request carries a suggested rule).
- **AskUserQuestion** (multiple choice): one page per question ("1/3"); each option is its own row;
  - single-select: tap selects (highlight), **Send** confirms (disabled until something is selected);
  - multi-select: checkboxes, **Send**;
  - long-press shows the option's description; vertical scroll for long lists;
  - with several questions, Send on the last page sends all answers;
  - **Other 🎤** (Phase 3).
- Answer delivery is verified first in implementation. Preferred: allow with `updatedInput` carrying the answers.
  Fallback (documented, always works): **deny with a reason** "The user answered on the board: <question> → <choice>"
  so Claude proceeds with that choice.
- "Always allow": use the documented rule mechanism if verified; otherwise the button is not shown.

### Protocol
New board message kinds on the existing encrypted Claude characteristics (same chunking):
session list/delta, focus, question (questions + options), and answers carrying option indexes or text.
Ids are never 0; only the request shown on the board can be answered.

## Phase 3: voice commands (near the Mac)

- Claude screen 🎤: tap to start, auto-stop after ~1.5 s silence or tap again. The level ring tracks the voice;
  partial transcript is shown live.
- Audio: board mic → ADPCM over the Mac BLE link, only while recording; translation streaming to the iPhone pauses meanwhile.
- The Mac transcribes on device (SpeechAnalyzer, Vietnamese by default).
- Confirmation is mandatory: transcript with **Say again / Cancel / Send**.
- Send → the daemon types the text into the focused session's tmux pane (`send-keys -l`, control characters
  stripped, one Enter at the end). If Claude is working, the text queues like typed input.
- Voice is also used for **Other** answers and **Deny with reason**.
- `cb` launcher: starts `claude` (with any arguments) inside a tmux session named after the project; Remote Control
  works as usual. Sessions without a tmux pane show a disabled 🎤 with "Open with `cb` for voice".
- Errors: no Mac link → 🎤 hidden; empty transcript → "Didn't catch that, say again"; tmux failure → error shown, nothing sent.

## Phase 4: iPhone notifications (ANCS)

- The board acts as an ANCS client on the iPhone link (encrypted, bonded; one-time pairing prompt on the iPhone).
- Only notifications from the Claude app are shown (filtered by app identifier); chime + text on the board, wake if locked.
- If a notification offers positive/negative actions, the board shows them as buttons and performs the action on tap.
- Works without the Mac and without the translator app running.
- First step of the phase: verify on the user's iPhone which actions Claude app notifications expose.

## Phase 5: relay through the iPhone (away from the Mac)

- The Mac daemon listens on its Tailscale address only, with a shared secret generated at install; the installer
  prints a QR code (address + secret) that the iPhone app scans once.
- The iPhone app relays Claude messages between the board (BLE) and the Mac (WebSocket over Tailscale), using the
  same message format as the direct link. It does not interpret or answer anything itself.
- Path selection: the board prefers the direct Mac link, otherwise the relay; the daemon prefers direct BLE, otherwise the relay.
- Voice away from the Mac: the iPhone transcribes the board audio and relays text only.
- Security: WireGuard (Tailscale) + secret; the port is not exposed to the internet; all existing id checks apply; never auto-approve.
- The iPhone app must be running (it runs in the background for the translator anyway). Free developer accounts
  require reinstalling the app every 7 days.

## Out of scope
- Reading the Claude app's data or using Anthropic's private Remote Control protocol.
- Board Wi-Fi.
- Pure cloud sessions (claude.ai/code without a Mac).

## Testing
- Mac: unit tests for session tracking, message encoding, answer mapping (allow/updatedInput and deny-with-reason
  fallback), tmux text sanitising; fake-board tests for the daemon.
- Firmware: host tests for the protocol parser; on-device checks for buttons, lock face, picker, question pages,
  arming, voice capture.
- End to end on hardware with the user: real Claude session (permission, AskUserQuestion with multiple questions,
  Always allow), voice command into a `cb` session, ANCS notification from the Claude app, relay with the Mac out of range.
